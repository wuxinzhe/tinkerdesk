## 3. 架构分析

```
┌─ renderer（Vue 3 SPA）───────────────────────────────┐
│  views（agents/chat/settings/workshop）→ stores → api │
│  api 层：AgentApi 抽象（AgentLocal 走 IPC，预留 remote）│
└──────────────┬───────────────────────────────────────┘
               │ contextBridge（window.api，约 60+ IPC 通道）
┌─ preload ────┴───────────────────────────────────────┐
│  统一 inv() 封装：日志 + apiKey 脱敏 + 全局错误提示    │
└──────────────┬───────────────────────────────────────┘
┌─ main（Electron 主进程）─────────────────────────────┐
│  controller 层（22 个，纯 IPC 绑定，无业务逻辑）       │
│  core 层：                                            │
│    loop/   TinkerAgent（每会话实例）→ SessionRuntime  │
│            → Conversation → ToolCallExecutor         │
│            → ApprovalManager                         │
│    llm/    LlmRouter（场景路由+多模型回退）           │
│            → LlmClientManager → 3 家 SDK 客户端       │
│            → LlmOperationManager（chat/summary/title）│
│    tool/   ToolManager（builtin/client/mcp 统一注册） │
│            + McpToolCenter（stdio/http 双传输）       │
│    prompt/ PromptManager + 11 个模块化 prompt 模块    │
│            + Handlebars 渲染 + 会话级缓存             │
│    plugin/ PluginManager（manifest + 契约校验 +       │
│            systemInterfaces 声明式 provider 注册）    │
│    mode/   AgentModeRegistry（agent 模式扩展点）      │
│  service 层：约 20 个服务（内存/技能/压缩/沙箱/授权） │
│  repository 层：SQLite 仓储（~17 个表）               │
└──────────────────────────────────────────────────────┘
```

**依赖组装**：`bootstrap.ts` 手工 DI（无容器），单入口集中接线，可读性好，但 395 行的大函数会随功能膨胀。

**分层评价**：Controller → Service → Repository 分层干净；工具、LLM、Prompt 均做了接口抽象 + 可插拔注册，扩展点设计成熟。这是本项目最大的优点。

## 4. 核心子系统评估

### 4.1 Agent 循环（loop/）
- 每会话一个 `TinkerAgent` 实例（OO 化重构已完成），消息队列 per-session 串行，中断/撤回/审批生命周期完整。
- 工具执行链：循环防护（失败计数/同工具失败/无进展）→ 三层门检（灾难 DENY / 授权 ASK / 沙盒白名单）→ 审批 → 执行 → 缓存失效。**设计上是加分项。**
- 上下文：SessionContext → ConversationContext → ToolContext 三级，配置一次性装载。

### 4.2 LLM 层
- 统一 `LlmResponse` 判别式（SUCCESS/RETRYABLE/FATAL），按场景路由到 Operation，多模型配置顺序回退——比多数同类客户端成熟。
- 流式处理完整：文本/推理内容/多工具调用分路累积，兼容 DeepSeek reasoning_content、各家 cache token 统计。
- 注意点：客户端 timeout 硬编码 60000ms，无重试/退避策略（仅靠模型级回退）。

### 4.3 工具与 MCP
- 25+ 内置工具（终端、文件、搜索、抓取、TTS/STT、定时器、子代理 delegate、computer-use 桌面自动化）。
- MCP 支持 stdio + HTTP 双传输，工具定义持久化到库（避免重启反复 discover），动态注册进统一 ToolManager。
- 工具禁用黑名单 per-profile 持久化。

### 4.4 Prompt 体系
- 模块化 prompt 构建（系统上下文/运行时环境/工具强制/任务完成/记忆快照/用户画像/技能索引/灵魂提示等 11 个预设模块），支持自定义模块 + 会话级缓存失效——设计领先于多数同类项目。

### 4.5 插件系统
- manifest.json + CommonJS 加载 + apiVersion 1 契约（强制 `check()` 自检）+ systemInterfaces 声明式接口注册（voice/web.search/web.extract）。
- **安全模型（v1 信任制）**：插件 = main 进程任意代码权限。zip 安装走系统 tar 解压，**无签名/哈希校验**。文档已明示"用户手动下载解压 = 主动信任"。对单用户本地工具可接受，但这是供应链上最大的单点风险。

### 4.6 数据层
- 单文件 SQLite（WAL），schema 复刻服务端（sessions/conversations/messages 含 token/成本统计）。
- **最大短板：schema 演进直接 DROP TABLE 重建**（`ensureSessionSchema` 等注释明示"开发阶段…不迁移数据"），messages 列迁移有幂等 ALTER，但 sessions/user_scene_models/private_skill_related 会**丢数据**。进入正式版前必须换成真正的迁移机制。

### 4.7 前端
- 组件体系自洽（Sa* 系列 + workspace 系列 + Naive UI 混用），主题系统（forest/ocean）、流式打字机/段落分割、移动端响应式（375px 手机模式）。
- AgentApi 抽象层支持 local/remote 切换（Web 版走 HTTP/STOMP 到 8080 后端）。

## 7. 安全性评估

**做得好的：**
- 灾难命令正则拦截（rm -rf /、format、mkfs、shutdown、fork bomb 等）→ DENY 不进审批直接拦截
- 危险操作（递归删除、chmod 777、curl|sh、编码混淆执行、git force push 等）→ ASK 审批
- URL/路径白名单沙箱 + 审批通过自动加白
- YOLO 模式可跳过检查（显式开关）
- computer_use 工具按键/输入硬封锁（防锁屏/危险组合键）
- 工具循环防护（防 agent 陷入重复失败）

**注意点：**
1. `sandbox: false`（Electron 层）。依赖默认 contextIsolation=true + nodeIntegration=false 兜底，但主窗口无 CSP，`window.api` 全量暴露且 **IPC handler 无 sender 校验**——一旦 renderer 被 XSS/导航到不可信页面，攻击面是全部 60+ 通道。建议：`will-navigate`/`setWindowOpenHandler` 拦截 + 关键通道校验 `event.senderFrame.url`。
2. 插件无签名校验（见 4.5）。
3. 语音权限 handler 直接允许全部 media 请求（`callback(permission === 'media')`）——窗口内任何页面都能开麦克风，结合第 1 点需留意。

## 9. 结论

**总体评价：架构优秀、工程质量中上、工程化配套明显滞后。**

这是一个设计意图清晰、分层干净、扩展点成熟（LLM 路由/工具注册/插件 provider/prompt 模块都是教科书式的可插拔设计）的本地 Agent 客户端。安全门检（灾难命令/审批/沙箱）的完备度超过同类项目平均水平。

当前最大的负债不在代码本身，而在**工程化护栏缺失**：53.7k 行核心逻辑零测试、无 CI、无 typecheck 门禁、schema 迁移会丢数据。这些在单机开发阶段不致命，但任何一次"多模型回退逻辑调整"或"agent 循环重构"都可能引入难以发现的回归——而这类重构恰恰是这个项目提交历史里最频繁的动作（87 个提交中大量 refactor）。

**建议动作顺序**：
1. 补 vitest + 核心逻辑单测（LLM 回退、工具门检、压缩、message 落库）—— 1-2 周
2. schema 迁移机制替换 DROP TABLE —— 0.5 周
3. CI（lint + typecheck + test）+ 移除 sql.js —— 0.5 周
4. CSP + IPC sender 校验 —— 0.5 周
